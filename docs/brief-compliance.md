# Brief compliance — every pass/fail gate, and where the code proves it

The assignment brief defines technical pass/fail gates. This document maps each
one to the exact code that satisfies it. The professor can open the repo, see
the live queries, and run the pipeline.

## Gate 1 — At least one agent connects to a live external data source (tool call / MCP), queried at the moment of use

**Satisfied — three live sources, plus a real MCP server.**

- Live queries (network calls at runtime, nothing hardcoded):
  - `backend/live_data.py` — `fetch_events()` calls the live Fáilte Ireland
    events API; `fetch_weather()` calls the live Open-Meteo API;
    `fetch_destination_interest()` calls the live Wikimedia pageviews API.
  - These are plain HTTP requests made **every time** an agent calls the tools
    `query_live_events`, `query_live_weather`, `query_destination_interest`
    (`backend/toolkit.py`).
- Real MCP server: `backend/mcp_server.py` is a Model Context Protocol server
  exposing 12 hotel tools; `backend/mcp_client.py` connects to it over stdio.
  Every call is recorded with a timestamp (`fetched_at`) as evidence.
- The Researcher (Eleanor) is the agent that connects: her system prompt
  (`backend/agents.py`) instructs her to call these tools and only use what she
  verifies herself.

**Code location:** `backend/live_data.py`, `backend/toolkit.py`,
`backend/mcp_server.py`, `backend/mcp_client.py`, `backend/agents.py`.

## Gate 2 — Synthetic data lives in a real, queryable source, fetched by the agent at query time (not hardcoded into code or prompts)

**Satisfied.**

- The hotel's business data is generated into a real **SQLite database**
  (`backend/data/hotel.db`) by `backend/seed.py` on server start. It is not
  typed into any prompt and not hardcoded into the pipeline.
- The agents fetch it **dynamically** through MCP tools
  (`get_hotel_status`, `get_available_inventory`, `get_historical_performance`,
  `calculate_package_economics`, …) at query time.
- The database schema lives in `backend/hotel_db.py`; the seed is deterministic
  (`random.seed(2026)`) and dated relative to today so the story is always
  "this coming weekend".
- A frozen snapshot of the dataset is exported to `docs/data/*.json` for
  transparency (generated by `backend/export_data.py`), but the live system
  never reads those files — it queries the database.

**Code location:** `backend/seed.py`, `backend/hotel_db.py`,
`backend/mcp_server.py`.

## Gate 3 — Submit a zip with the complete codebase; dynamic access verified in code

**Satisfied — the code is the proof.** A professor inspecting the source will
find real HTTP clients (`urllib.request` calls with live URLs), a real SQLite
engine, and a real MCP stdio connection. There is no "data" array with
hardcoded results anywhere. Run the pipeline and the live values (current
Dublin weather, real Fáilte Ireland events, database occupancy) appear in the
UI with timestamps.

**Satisfied.**

- The submission zip is built excluding `.git`, `.venv`, `node_modules`,
