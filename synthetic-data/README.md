# VIRELLE — Synthetic vs Live data (what is real, what is not)

This is the honest data ledger for the VIRELLE demo. The system blends two very
different kinds of data, and it is important to know which is which.

## The one-sentence answer

**The hotel is fictional and its operational data is synthetic; the destination
data is real, fetched live from the internet at the moment of use.**

| Data | Real? | Source |
|------|-------|--------|
| Dublin events this weekend | ✅ **Real, live** | Fáilte Ireland Open Data API |
| Dublin weather forecast | ✅ **Real, live** | Open-Meteo API |
| Dublin destination interest | ✅ **Real, live** | Fáilte Ireland tourism catalogue |
| The Virelle Dublin as a hotel | ❌ **Fictional** | Defined in `seed.py` |
| Room inventory / occupancy | ❌ **Synthetic** | Generated in `seed.py` |
| Facility utilisation | ❌ **Synthetic** | Generated in `seed.py` |
| Historical performance | ❌ **Synthetic** | Generated in `seed.py` |
| Past bookings | ❌ **Synthetic** | Generated in `seed.py` |
| The experience / campaign / decision | ✅ **Real LLM output** | OpenAI (gpt-4o) at runtime |
| Evidence (every tool call) | ✅ **Real** | Recorded at runtime |

## What is real (live external intelligence)

These are genuinely fetched over the network **every time the organisation runs**
and are shown as live connections in the UI:

- **Events** — `Fáilte Ireland Open Data` CSV endpoint. Filtered to Dublin in the
  next 14 days, dates parsed from `DD/MM/YYYY`, read with `utf-8-sig`. The
  "Big Grill Festival 2026" event the organisation keeps discovering is a **real
  listing** from that live feed.
- **Weather** — `Open-Meteo` forecast for the hotel's coordinates
  (53.3498, −6.2603), WMO codes mapped to human labels.
- **Destination interest** — `Fáilte Ireland Open Data` tourism catalogue
  (attractions & experiences CSV), filtered to Dublin county — 1,259 registered
  attractions, 333 tours/experiences, 559 food & drink venues.

The large Fáilte Ireland catalogues are reused for short freshness windows
(events 5 min, tourism 15 min) so the free-tier bandwidth quota is never
exhausted; weather is fetched live every time, and every agent tool call forces
a fresh fetch. When a feed is quota-limited, an honestly-labelled curated
snapshot of the real listings is served (`curated_events.json`,
`curated_tourism.json`) so the connection monitor never dead-ends.

Nothing about the destination is invented. If the feed returns nothing, the
agent is told live data is unavailable.

## What is synthetic (the fictional hotel)

The Virelle Dublin does not exist. Its entire operational surface is generated
by `backend/seed.py` into a real SQLite database on every server start. The
generator uses `random.seed(2026)` so it is reproducible, and all dates are
computed **relative to the current date** so the storyline is always "this
coming weekend".

Tables and their synthetic story:

| Table | Rows | What it is | The story it tells |
|-------|------|-----------|--------------------|
| `hotel` | 1 | The hotel profile | 5-star boutique, 84 rooms, Dublin city centre |
| `rooms` | 84 | Room inventory | 6 categories — Classic (30), Deluxe (24), Junior Suite (10), Signature Suite (10), Rooftop Duplex (6), Ambassador Suite (4) |
| `facilities` | 5 | Spa, restaurant, rooftop bar, private dining, chauffeur | Under-utilised midweek (e.g. spa 42%, restaurant 38%), rooftop bar busier at 66% |
| `inventory` | 21 | Unsold rooms per night (next 21 days) | **Saturday = 31 unsold** (the bottleneck the agents exploit), Friday 24, Sunday 38, weekdays ~12–16 |
| `historical_performance` | 16 | Weekly occupancy / ADR / RevPAR | Occupancy 58–86%, couples demand index highest (0.70–0.95) |
| `packages` | 3 | Existing (non-event-led) packages | Spa Day Retreat €249, Culinary Evening €310, City Uncovered €495 — all partially sold |
| `bookings` | 720 | Past 90 days of history | 46% couples, revenue multipliers by segment |

The **721st booking** in the live database is real: it is the reservation the
demo wrote when a booking was made through the product page (ref
`VR-260814001640-2`).

## How the agents use the blend

1. **Eleanor (Researcher)** reads the **real** live events/weather/destination
   data and queries the **synthetic** hotel via MCP tools.
2. The pitch she forms — e.g. "31 unsold rooms on Saturday, a real food
   festival in Dublin, weather suitable for indoor dining" — is therefore a
   **genuine intersection** of real destination facts and synthetic hotel facts.
3. The **product, campaign and decision** are generated by the LLM from those
   facts, so each run differs.

## Repository snapshots

The `docs/data/` folder contains a frozen snapshot of the synthetic database,
exported by `backend/export_data.py`:

- `hotel.json`, `rooms.json`, `facilities.json`, `inventory.json`,
  `historical_performance.json`, `packages.json`, `bookings.json`
- `manifest.json` (row counts + export timestamp)

These files are documentation, not runtime state. The live SQLite file lives at
`backend/data/hotel.db`, is regenerated on every start, and is gitignored.
